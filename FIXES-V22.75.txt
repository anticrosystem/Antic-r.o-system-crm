ANTIC R.O SYSTEM CRM — V22.75 BUG FIX BUILD
==========================================

Applied fixes
-------------
1. Dashboard Low Stock now reads the same lowStock field used by Inventory.
2. Date-only values now use the browser's local calendar date instead of UTC ISO slicing.
   Date arithmetic for addDays and the quotation validity date uses the same local-date formatter.
3. Normalized Firestore sync no longer physically deletes cloud documents merely because they are absent from the current device's local array. This prevents an incomplete/stale device snapshot from deleting cloud-only records.
4. Cloud sync requests made while another sync is running are queued for a follow-up sync rather than silently discarded.
5. Editing a service now reverses its prior inventory movements before applying the edited parts/status. Moving a completed service back to an open/non-completed status restores its recorded stock movements.
6. Apple touch icon now points to the current Antic R.O System icon.
7. App title/header/cloud metadata and service-worker cache version updated for this repair build.

Static verification
-------------------
- All 8 inline JavaScript blocks pass Node.js syntax checks.
- manifest.json parses successfully.
- Both manifest icon files exist.
- No remaining toISOString().slice(0,10) date-only conversions found in index.html.
- Dashboard no longer reads the obsolete inventory.low field.

Important limitations
---------------------
- Firebase sign-in, actual Firestore rules deployment, live sync across two devices, invoice printing/PDF, and real customer-data recovery were not testable without the user's live Firebase/browser session.
- Firestore normalized collection sync is now non-destructive for cloud-only documents. Explicit record deletion propagation still requires a deliberate tombstone workflow; do not assume that deleting a local record removes every normalized cloud copy.
- Take a CRM JSON backup before replacing the live site. Deploy the complete ZIP contents together, then open the CRM online once to activate the updated service worker.
