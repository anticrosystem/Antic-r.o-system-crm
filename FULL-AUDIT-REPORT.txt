REMAINING RISKS / NOT VERIFIED LIVE
-----------------------------------
1. Firebase project configuration is present in client code. Firebase web API keys are generally public identifiers, not secrets; security depends on Authentication settings, authorized domains, Firestore rules, and project restrictions. Verify these in Firebase Console.
2. Firestore rules in this package must actually be published to the connected Firebase project. Static code cannot confirm deployment state.
3. Live sign-in, password reset, account creation, cross-device sync, concurrent edits, offline-to-online recovery, invoice/PDF generation, WhatsApp links, stock/payment calculations, and deletion/restore flows were not run against a real browser and Firebase project.
4. CRM records are stored in browser localStorage. Anyone with access to the same unlocked browser profile may be able to access them; use device screen lock and avoid shared devices. Browser storage is not a backup.
5. Sync behavior should be tested with a backup and two test accounts/devices before real data use. Do not test destructive actions on production data.
6. External CDN scripts (Firebase compat SDKs and html2pdf.js) require internet access unless separately cached by the browser.
7. The Service Worker caches the main HTML page; this does not guarantee every feature works offline, especially Firebase/cloud features and external CDN libraries.

RECOMMENDED SAFE TEST PLAN
--------------------------
- Make a backup/export from the current CRM before deploying.
- Deploy the files to the intended GitHub Pages repository root.
- Open the site online and confirm the new service worker activates.
- Sign in with a test account and confirm a record appears only in that account.
- Create a test customer, sale, payment, service and AMC; verify totals and history.
- Test on a second device using the same account; verify sync.
- Test offline reopening, reconnecting, and invoice PDF/print.
- Verify Firestore rules in Firebase Console before storing real customer data.

The package passes the listed static checks and the identified PWA cache issue has been repaired. It is NOT certified error-free until the remaining live tests are completed.
